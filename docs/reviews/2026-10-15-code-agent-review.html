1. Short answer

The core idea is correct for editing: the harness owns the file, the model writes only the changed function, and free checks (ast, import, tests) judge the result.

The live named edit shows this: 2 model calls, 55 output tokens, 9 seconds, correct fix.

The exploration part is the weakest part. It is not the strongest part, as the design needs.

Navigation picks the target with a keyword score and no model call. When the score is wrong, the agent spends hundreds of tokens on generation in the wrong function.

The live unnamed edit shows this: 12 calls, 936 output tokens, 126 seconds, no fix. The wrong function was chosen for free.

There is also a safety problem. Model code runs without a sandbox in your working directory, with your environment (API keys). The edit mode can write wrong code to your files and report success.

Fix safety first. Then change navigation to a flat, ranked symbol menu that the model confirms.

F. Routing (design tension with the "no regex" standard)

The code sub-router uses fixed keyword lists. Spike E7 measured them at 97.9% precision, but only on 69 English requests written by the project, in which no verb was also a function name.

Under real use, the free route sends read-only questions to edit (B, P1) and to compute. It also sends "fix the build function in parser.py" to author.

The saving per request is about 3 tokens. The cost of a misroute is a rewritten file. Recommendation: allow free routes only to read-only navigate; send every other case to the 1-token menu.

The top-level agent description ("write or debug Python code") does not mention navigate or compute, so those requests usually go to web or files (I).

4. Is the design right for minimum-token coding?

What is right (keep it)

The model writes only the changed function, never the whole file. In the live named edit this cost 55 output tokens.

Free judges (ast, import, a caller test) replace model judgement. This is the strongest idea in the project.

Generation gets a fresh, stateless prompt and repair resamples blindly (E5b). Menus keep the session log.

A symbol index replaces reading whole files into the prompt. It is the right base for cheap exploration.

What is wrong (change it)

1. The most important decision has no model check. The target ("where") is chosen by a keyword score. The only check afterwards is "the module imports". A wrong target costs much more than a 3-token confirmation menu would.

2. Tree navigation does not scale. A folder → file → def walk needs one decision per level and is cut off at depth 1. A flat ranked list does not depend on depth.

3. Exploration has no call graph. Bugs are often in a function that the named function calls. The index already collects call sites, but nothing uses them.

4. Without a test, "success" means only "it imports". The agent always runs without a test, so the edit result is unverified, yet the file is still written.

Proposed direction (no code changed yet)

#ChangeToken effect
1Safety envelope: sys.executable -I, temp cwd (or files_root for compute, read-only by intent), scrubbed env, rlimits, process-group kill, capped and replace-decoded output. Edit: show a diff and ask before writing; byte-exact backup; try/finally restore.0
2Flat symbol shortlist: rank all indexed symbols at once by qualname, path, docstring and identifiers, normalized by length (BM25-style). Show the top 8 as one menu: qualname — path — first doc line. This replaces the folder/file/def walk.about 3 tokens; depth-independent
3Confirm by pointing: show the chosen function and ask one menu: "1 = the problem is in this function / 2 = in a function it calls (list callees from call_sites) / 3 = somewhere else".about 3 tokens per hop; saves 100-900 tokens per wrong target
4"Unchanged" means "move on": when the generation returns the original function, relocate at once instead of resampling.saves up to about 900 tokens (live case)
5Free oracle from the repo: find the existing tests that reference the target (call sites in tests/), run them before and after the edit, and use them as the trusted check.0 model tokens
6Generation hygiene: reject output cut by the token cap; skip the identical temperature-0 retry; prefill the original def line exactly (keeps async, defaults, annotations); keep the docstring.saves about 1 wasted generation per failure
7Routing: free routes only to navigate; edit and compute always go through the menu (or the confirmation in #1).+3 tokens on some requests

Point 2 also matches your "no regex for semantic choice" standard better than the current code. The lexical score only orders the list. The model makes the choice.

Author mode (plan → per-method generation) was designed for 1.5B models. On 27B models, the plan parser is too strict for markdown output and falls back to a single main() (C, plan row). This should be measured before more is built on the plan step.

5. Hypotheses checked and refuted

Path traversal in edit: not possible. Paths come only from the index; symlinks are excluded.

Step budget and termination: bounded in both verticals.

Traceback blame line mapping: correct for nested defs, lambdas, chained exceptions, and multi-line strings.

Stop sequences: they do not cut nested defs, decorators or indented prints.

The closed think block (today's fix) sits correctly before every generation prefill.

A wrong trusted anchor from plan.py: not possible (plan asserts are advisory only).

Decorators are kept on replace.
